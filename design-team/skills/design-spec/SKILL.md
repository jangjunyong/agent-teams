# design-spec 규격

디자인팀의 design 그래프는 **방향서+목업(A·B 병렬) → 비평표 → 디자인 스펙** 순으로 흐른다. 각 단계는 앞 단계 파일만 근거로 삼고, 근거는 항상 `파일경로#섹션` 또는 `파일경로:<선택자|줄번호>` 로 적는다. 이 규격에 없는 섹션을 빼거나 이름을 바꾸면 다음 노드가 읽지 못한다.

## 0. 공통 규칙

- frontmatter 필수 3 + 권장: `type` `status` `owner` 는 없으면 `node done` 이 실패한다. `inputs`(읽은 파일 경로 목록) `created`(YYYY-MM-DD) `run`(run_id) 을 함께 쓴다
- **status 는 `draft | in-review | approved | rejected` 네 값뿐이다.** 방향서·비평표는 항상 `draft`. 디자인 스펙은 비평 승자가 있으면 `in-review`(verify-team 검증 대기), 없으면 `draft`. 디자인팀은 `approved` 를 쓰지 않는다 — 승인은 verify-team 판정 뒤 오케스트레이터의 일이다(G3)
- **근거 표기**: md 는 `_work/design/<stem>.dir-a.md#2`, HTML 은 `_work/design/<stem>.dir-a.html:.hero h1` 또는 `:L120` 처럼 요소를 지목한다. "전반적으로" 는 근거가 아니다
- **색은 hex 6자리**(`#1F2A44`), 서체는 실제 패밀리명 + 폴백 스택, 크기는 `px` 와 `rem` 병기
- **대비비는 계산값이다** (WCAG 2.x): 각 채널 `c/255` → `c≤0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`, `L = 0.2126R + 0.7152G + 0.0722B`, 대비비 `(L밝+0.05)/(L어둠+0.05)`, 소수 1자리. "충분해 보인다" 는 대비비가 아니다. 비평가는 방향서가 적은 값을 믿지 않고 다시 계산한다
- 원문(기획/스펙 md)에 없는 콘텐츠·기능·수치를 만들지 않는다. 목업에 필요한데 원문에 없는 문구는 `[원문에 없음 — 가정]` 을 붙인다
- 파일 위치: 중간 산출물은 `_work/design/`, 디자인 스펙만 `_work/<stem>.design-spec.md` (검증 대상 파일이므로 verify 그래프가 찾기 쉬운 곳). `deliverables/` 에는 쓰지 않는다
- 길이: 방향서 ≤ 1,500자 · HTML 목업 ≤ 600줄 · 비평표 제한 없음(체크리스트 전 칸 채움) · 디자인 스펙 ≤ 3,000자

## 1. 디자인 방향서 (direction) — `_work/design/<stem>.dir-{a|b}.md`

방향 하나로만 쓴 독립 제안. 방향은 노드 프롬프트가 주입한다.

| 노드 | direction | 최우선 | 의도적 후순위 |
|---|---|---|---|
| direction_a | `editorial` 절제된 편집형 | 타이포그래피·여백·그리드·읽는 흐름. 중립 팔레트 + 악센트 1색 | 시각적 임팩트, 컴포넌트 밀도 |
| direction_b | `product` 대담한 제품형 | 강한 색 블록·큰 숫자·명확한 CTA·컴포넌트 시스템. 다크 배경 허용 | 절제, 긴 글 가독성 |

```markdown
---
type: design
status: draft
owner: design-team:visual-designer
direction: editorial | product
inputs: [<기획/스펙 md 경로>]
mockup: _work/design/<stem>.dir-<a|b>.html
created: YYYY-MM-DD
run: <run_id>
---
# 디자인 방향 A|B: <한 줄 제목> (방향: <direction>)

## 1. 주제 해석
(원문이 무엇을 위한 화면/문서인지, 1차 사용자와 그가 첫 5초에 해야 할 일. 원문 어느 섹션에서 끌어냈는지 `경로#섹션`)

## 2. 팔레트 (4~6색)
| 역할 | 이름 | hex | 용도 | 주제에서 끌어낸 이유 |
|---|---|---|---|---|
(역할: 배경·전경(본문)·악센트·보조·상태 중. **본문 전경/배경 대비 4.5:1 이상** 을 수치로 적는다. 템플릿 팔레트·보라 그라데이션 금지 — 5절)

## 3. 서체 (2종 이상)
| 용도 | 패밀리 | 폴백 스택 | 굵기 | 이유 |
|---|---|---|---|---|
(제목·본문 최소 2종. 외부 폰트 로딩 없이 목업에서 실제로 렌더되는 스택이어야 한다 — 시스템/웹세이프 폰트 우선. Inter 단독 금지 — 5절)

## 4. 레이아웃 개념
(그리드(열 수·거터·최대 너비), 여백 스케일, 위계 규칙(제목/본문/보조 3단 이상), 주요 화면 1개의 와이어 설명. 문단 1~2개)

## 5. 시그니처 요소 (정확히 1개)
(이 방향을 다른 방향과 구분하는 단 하나의 시각 장치 — 예: 좌측 세로 규칙선 + 번호 체계, 카운터 스타일 큰 숫자 블록. 목업 어느 요소(선택자)에 구현했는지)

## 6. 피한 AI 디자인 클리셰
(5절 목록에서 이 방향이 특히 빠지기 쉬운 항목 3개 이상과, 대신 무엇을 했는지)

## 7. 이 방향이 포기한 것 (최소 2개)
(의도적으로 후순위에 둔 것과 이유. 비평가가 다른 방향과 비교할 때 쓴다)

## 8. 가장 약한 고리
(이 방향이 무너진다면 어디서 먼저 무너지는가 — 1개, 이유. 빈칸 금지)

## 9. 근거
(원문 인용 `경로#섹션`, 가정은 `[원문에 없음 — 가정]`)
```

## 2. HTML 목업 — `_work/design/<stem>.dir-{a|b}.html`

방향서와 같은 노드가 쓴다. 비평가는 **이 파일을 실제 근거**로 삼는다 (방향서의 주장이 아니라).

규칙:
- **단일 파일.** `<style>` 인라인, `<script>` 는 없거나 인라인. **외부 의존 0** — CDN·Google Fonts `<link>`·외부 이미지·iframe 금지. 이미지가 필요하면 인라인 SVG 또는 CSS 도형
- `<!doctype html>` `<html lang="ko">` `<meta name="viewport">` 포함. 시맨틱 랜드마크(`header` `nav` `main` `section` `footer`) 사용
- **실제 콘텐츠.** 원문(기획/스펙 md)의 기능명·문구·수치를 그대로 쓴다. lorem ipsum·"제목 텍스트"·"설명이 들어갑니다" 류 자리표시 금지. 원문에 없는 문구는 최소화하고 `<!-- 가정 -->` 주석을 단다
- 방향서 2절 팔레트·3절 서체를 CSS 변수(`--color-*`, `--font-*`)로 선언하고 그 변수만 쓴다. 방향서에 없는 색이 CSS 에 있으면 비평에서 '일관성' 감점
- 접근성: 본문 대비 4.5:1 이상, 포커스 스타일(`:focus-visible`) 명시, 모든 인터랙티브 요소는 `<a>`/`<button>`/`<input>`(div 클릭 금지), 이미지·아이콘 SVG 는 `aria-label` 또는 `aria-hidden`
- 반응형: 최소 1개 브레이크포인트(`@media`) 에서 레이아웃이 바뀐다. 고정 px 너비로 가로 스크롤이 나지 않는다
- 상태: 버튼·링크·입력의 hover/focus/disabled 중 2개 이상을 CSS 로 보여준다. 상태색(성공·경고·위험·정보) 중 원문에 쓰임새가 있는 것은 실제 컴포넌트로 1개 이상 표시
- 길이 ≤ 600줄. 화면 1~2개(핵심 화면 + 보조 1개)면 충분하다. 페이지 수로 점수를 얻지 않는다
- 첫 줄 주석: `<!-- design-team direction=<a|b> stem=<stem> source=<원문 경로> -->`

## 3. 비평표 (critique) — `_work/design/<stem>.critique.md`

두 방향을 같은 체크리스트로 채점하고 승자 하나를 고른다. 적대적 문서다 — 칭찬·완충 문장 없이 쓴다. **근거는 HTML 파일의 요소(선택자·줄)여야 한다.** 방향서의 자기 설명은 근거가 아니다.

```markdown
---
type: analysis
status: draft
owner: design-team:design-critic
inputs: [<원문>, <dir-a.md>, <dir-a.html>, <dir-b.md>, <dir-b.html>]
winner: A | B | NONE
round: <회차>
created: YYYY-MM-DD
run: <run_id>
---
# 비평: <stem>

## 1. 체크리스트 채점 (1~5, 정수)
| 축 | A | B | 채점 기준 |
|---|---|---|---|
| 가독성 | | | 5=본문 16px↑·행간 1.5↑·줄길이 45~75자·대비 수치 충족 · 1=읽기 어려운 구간 있음 |
| 위계 | | | 5=제목/본문/보조 3단 이상이 크기·굵기·색으로 구분되고 첫 시선이 목적에 닿음 · 1=모든 게 같은 무게 |
| 일관성 | | | 5=CSS 변수만 사용, 간격·모서리·그림자 스케일 일관 · 1=방향서에 없는 색/임의 값 다수 |
| 접근성 | | | 5=대비 4.5:1 전부·focus-visible·시맨틱·aria 적절 · 1=div 버튼, 포커스 제거, 대비 미달 |
| 반응형 | | | 5=브레이크포인트에서 레이아웃이 실제로 바뀌고 가로 스크롤 없음 · 1=고정 너비 |
| AI 티 | | | 5=5절 클리셰 0건·시그니처 요소가 주제에서 나옴 · 1=클리셰 3건 이상 또는 템플릿 그대로 (점수가 높을수록 AI 티 적음) |
| 콘텐츠 충실도 | | | 5=원문 문구·수치 그대로, 자리표시 0 · 1=lorem/자리표시 또는 원문에 없는 기능 |
| **합계** | | | 35점 만점 |

## 2. 축별 근거 (14칸 전부)
### 가독성
- A <점수>: 근거 `경로:선택자|줄` → 반박(왜 더 못 줬는가)
- B …
### 위계 / ### 일관성 / ### 접근성 / ### 반응형 / ### AI 티 / ### 콘텐츠 충실도 (같은 꼴)

## 3. AI 클리셰 적발표
| 방향 | 클리셰(5절 번호) | 위치(선택자|줄) | 심각도(치명|보통) |
|---|---|---|---|
(0건이면 '0건 — 확인한 항목: …' 으로 무엇을 봤는지 적는다)

## 4. 규칙 위반
(2절 HTML 규칙 위반 — 외부 의존·lorem·div 버튼·브레이크포인트 없음 등. 위치 포함. 없으면 '없음')

## 5. 승자와 선정 사유 (3줄 이내)

## 6. 승자의 필수 수정 (스펙이 반드시 반영)
| # | 문제 | 위치 | 수정 방향 |
|---|---|---|---|

## 7. 패자에서 가져올 요소 (1개 이상 또는 '없음'+이유)
| 출처(경로:선택자) | 요소 | 승자에 어떻게 이식 | 비용 |
|---|---|---|---|

## 8. 버린 것
(살리지 않은 패자 요소와 이유 — 스펙 작성자가 다시 넣지 못하게)

## 9. NONE 일 때: 재작업 지시
(방향 a/b 별로 어느 요소·어느 규칙을 바꿔 다시 만들라. winner 가 NONE 이 아니면 '해당 없음')
```

**승자 규칙**
- 합계 최고. 동점이면 접근성 → AI 티 → 가독성 순으로 높은 쪽
- 다음 중 하나면 `winner: NONE`: (1) 최고 합계 < 21 (2) 두 방향 모두 접근성 또는 AI 티 축이 2점 이하 (3) 두 방향 모두 4절 규칙 위반(외부 의존·자리표시)이 있음
- 한 방향만 4절 규칙 위반이면 그 방향은 합계와 무관하게 승자가 될 수 없다
- 점수는 정수. 근거 없는 칸은 채점하지 않는다 — 근거가 없으면 1점이 아니라 '근거 부족' 으로 표기하고 해당 방향을 NONE 후보로 본다
- 치명 클리셰(보라 그라데이션 히어로·lorem·div 버튼·포커스 제거) 1건 = AI 티 또는 접근성 축 2점 이하

## 4. 디자인 스펙 (design-spec) — `_work/<stem>.design-spec.md`

오케스트레이터가 비평표와 승자 방향서·목업을 근거로 직접 쓴다. 구현자가 이 문서만 보고 CSS 토큰과 컴포넌트를 만들 수 있어야 한다.

```markdown
---
type: spec
status: in-review | draft
owner: design-team
verified_by: []
verify_round: 0
based_on: dir-a | dir-b
critique: <winner>
inputs: [<원문>, <critique>, <승자 dir md>, <승자 dir html>]
run: <run_id>
created: YYYY-MM-DD
---
# 디자인 스펙: <제목> (선정 방향 <A|B>, 미확정)

## 0. 방향 요약
(선정 방향·시그니처 요소·누구를 위한 화면인가 — 3줄. 승자 방향서 #1·#5 에서)

## 1. 색 토큰
| 토큰 | hex | 용도 | 배경 대비(비율) | 출처 |
|---|---|---|---|---|
(`--color-bg` `--color-fg` `--color-accent` … 이름 고정 접두 `--color-`. 본문 대비 4.5:1, 큰 텍스트 3:1 수치 기입. 비평 #6 수정 반영분은 출처에 `critique#6`)

## 2. 타이포 스케일
| 레벨 | 서체 | 크기(px/rem) | 행간 | 굵기 | 용도 |
|---|---|---|---|---|---|
(display·h1·h2·h3·body·small·mono 중 쓰는 것. 본문 ≥ 16px)

## 3. 간격·레이아웃
- 간격 스케일: (예 4·8·12·16·24·32·48·64)
- 그리드: 열 수 · 거터 · 최대 너비
- 모서리·그림자 스케일: (2단계 이내)

## 4. 컴포넌트 목록
| 컴포넌트 | 변형 | 상태(hover/focus/disabled/…) | 목업 근거(선택자) |
|---|---|---|---|
(목업에 실제로 있는 것 + 원문 기능에 필요한데 빠진 것은 `[목업에 없음 — 필요]`)

## 5. 상태색
| 상태 | hex | 전경 hex | 대비 | 쓰이는 곳 |
|---|---|---|---|---|
(success·warning·danger·info. 원문에 쓰임새 없는 상태는 '미사용' 표시)

## 6. 반응형 규칙
| 브레이크포인트 | 바뀌는 것 |
|---|---|

## 7. 접근성 규칙
(포커스 스타일·대비·시맨틱·키보드 순서·aria 최소 규칙 — 검사 가능한 문장으로)

## 8. 금지 목록
(5절 AI 클리셰 전부 + 비평 #3·#8 에서 이 프로젝트에 특정된 금지. 구현자가 "하면 안 되는 것" 목록)

## 9. 비평 반영 내역
```

## 6. status 규칙과 게이트

| 파일 | type | status (design-team 이 쓰는 값) | 이후 |
|---|---|---|---|
| dir-a/b (md+html) | design | draft | 비평 후 보존만. 갱신하지 않는다 |
| critique | analysis | draft | `winner: NONE` 이면 루프백 트리거 |
| design-spec | spec | winner A\|B → in-review · NONE 에스컬레이션 시 draft | `/verify-team:verify _work/<stem>.design-spec.md` → PASS 면 verify-team 이 `approved` + `verified_by` 추가. CONDITIONAL → `in-review`, FAIL → `rejected` |

- **루프백**: critique 가 NONE 이면 `_work/design/<stem>.critique.md` 를 `.critique.r<회차>.md` 로, 두 방향 4파일을 `.dir-a.r<회차>.md/.html` 등으로 보존하고, 다음 회차 direction 은 그 비평표의 `#9 재작업 지시` 를 추가 입력으로 받는다. 회차는 critique frontmatter `round` 로 추적. `policy.max_rounds`(2) 에 도달한 뒤 또 NONE 이면 사람 에스컬레이션 (두 비평표·네 방향 경로와 NONE 사유 보고)
- 디자인팀 에이전트는 `deliverables/` `runs/` 에 쓰지 않는다. 스펙을 `deliverables/` 로 옮기는 것은 G3 통과 뒤 오케스트레이터의 일이다
- 재실행 시 같은 경로의 dir 파일이 있고 최신이면 `node skip --note "기존 산출물 사용"`. 단 루프백 회차에서는 반드시 다시 만든다
